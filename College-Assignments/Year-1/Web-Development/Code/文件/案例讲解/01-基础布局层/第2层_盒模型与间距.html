📖 教学讲解区

📦 第2层：盒模型与间距

每个元素自己占多大地方——width、height、padding、margin

一、盒模型的四层结构

每个HTML元素都是一个"盒子"，由四层嵌套组成，从外到内：

margin（外边距）—— 我和邻居之间的距离
border（边框）—— 我的边界线
padding（内边距）—— 边界线和内容之间的缓冲
content（内容区）—— 文字/图片真正占的地方
/* 盒模型的CSS写法 */
.element {
    width: 300px;           /* 内容区宽度（border-box下是总宽度） */
    height: 200px;          /* 高度 */
    padding: 20px;          /* 内边距：内容到边框的距离 */
    border: 5px solid #333; /* 边框：5px粗、实线、深灰色 */
    margin: 30px;           /* 外边距：这个盒子和邻居的距离 */
}
/* 总宽度 = 300（width）+ 0（padding在border-box下算在width里）+ 0（border同理）+ 30×2（margin）= 360px */
/* 注意：margin不算在width里，即使border-box也不行！margin永远是"额外"的 */

二、width 的三种写法：固定 vs 弹性 vs 限制

写法含义什么时候用坑
width: 900px 永远900px，不管屏幕多大 几乎不用（除非你确定屏幕永远>900px） 手机375px→溢出
width: 100% 占满父容器的全部宽度 配合max-width使用 单独用在大屏上会太宽，文字难读
max-width: 900px 最大900px，小屏自动缩小 推荐 容器、卡片、内容区 需要配合width:100%才能在小屏撑满

❌ 你踩过的坑：ul 宽度写死 900px

旧代码：#content ul { width: 900px; }

问题：手机屏幕375px宽，900px的ul溢出屏幕，用户要横着滚。

修复：#content ul { max-width: 900px; width: 100%; }

因果关系：width写死 → 小屏幕溢出 → max-width限上限、width:100%保下限 → 大屏不超900、小屏自动缩

三、margin 塌陷 —— 第2层最阴险的坑

3.1 兄弟元素之间的 margin 塌陷

两个上下排列的块级元素，上面的有 margin-bottom: 30px，下面的有 margin-top: 20px。
直觉上间距应该是 30+20=50px，但CSS的规则是：取两者中较大的那个，所以实际间距只有 30px。

现场演示：

上元素 margin-bottom: 30px
下元素 margin-top: 20px

👆 两个元素之间的间距是 30px（取最大值），不是 30+20=50px

3.2 父子元素之间的 margin 塌陷

子元素的 margin-top 会"穿透"父元素，把父元素也一起往下推。

❌ 塌陷了

父元素（灰色背景）

子元素 margin-top:30px

↑ 子元素把父元素也推下来了

✅ 修复了

父元素 + overflow:hidden

子元素 margin-top:30px

↑ 子元素在父元素内部偏移

修复方案（任选其一）：

/* 方案1：父元素加 overflow: hidden（最常用） */
.parent { overflow: hidden; }

/* 方案2：父元素加 padding-top: 1px（破坏塌陷条件） */
.parent { padding-top: 1px; }

/* 方案3：父元素加 border-top: 1px solid transparent（透明边框也有效） */
.parent { border-top: 1px solid transparent; }

3.3 margin 塌陷的两条铁律

1. 只有垂直方向会塌陷，水平方向的 margin 不会合并。

2. 只有块级元素的 margin 会塌陷，flex子元素、inline-block元素不会。

四、padding 的妙用

/* padding 最常见的三个用途：*/

/* 1. 给内容留呼吸空间 */
.card { padding: 20px; }  /* 文字不贴边，看起来舒服 */

/* 2. 配合 border-box 做固定尺寸的按钮 */
.btn { width: 120px; padding: 10px 0; }  /* 不管字多字少，按钮都是120px宽 */

/* 3. 用 padding-top 百分比做固定宽高比的容器 */
.video-wrapper { padding-top: 56.25%; }  /* 16:9 的宽高比（9÷16=56.25%） */

五、calc() —— 让浏览器帮你算宽度

/* calc() 可以混合不同单位做运算 */
width: calc(100% - 30px);
/* 翻译：宽度 = 父容器100%宽度 - 30px */
/* 用途：3列布局，每列宽度 = (100% - 2个gap) / 3 */

/* ★★★ 最常见的致命错误 ★★★ */
/* ❌ 运算符两边没空格 → CSS引擎直接忽略整行！ */
width: calc(100%-30px);      /* 无效！当没写！ */
width: calc((100% - 30px) / 3);  /* ✅ 正确 */

/* 记法：calc当成文本输入框，加减乘除号像文字一样需要前后喘口气 */

❌ 你踩过的坑：calc 空格缺失

旧代码：width: calc((100%-30px)/3)

问题：减号两边没空格，CSS解析器认为100%-30px是一个无效的CSS值，整行丢弃。浏览器当作你没写width。

修复：width: calc((100% - 30px) / 3)

六、gap vs margin —— 你和第3层的经典冲突

核心原则：flex/grid 容器的子元素间距用 gap（第3层），不要用 margin（第2层）。

原因：gap 是父容器统一管理的"官方间距"，margin 是每个子元素自己设的"个人间距"。

两者同时存在 → 间距 = gap + margin → 和预期不符 → calc()算错 → 布局崩

/* ✅ 正确：父容器统一管间距 */
.container {
    display: flex;
    flex-wrap: wrap;
    gap: 15px;          /* 第3层：间距的唯一来源 */
}
.child {
    width: calc((100% - 30px) / 3);  /* 第2层：只算gap，不算margin */
    /* 没有 margin！*/
}

/* ❌ 错误：gap和margin同时管间距 */
.container { gap: 15px; }
.child { margin: 2px; }   /* 第2层又在管间距 → 打架！*/

七、因果关系链

width 写死 900px → 小屏溢出 → 改用 max-width + width:100%

父元素没设 overflow:hidden → 子元素 margin-top 穿透父元素 → 一起被推下去

calc() 减号两边没空格 → CSS引擎丢弃整行 → 宽度变回默认 → 布局崩

gap 和 margin 同时存在 → 间距变大(15+2+2=19px) → calc只减了gap → 宽度不够 → 溢出换行

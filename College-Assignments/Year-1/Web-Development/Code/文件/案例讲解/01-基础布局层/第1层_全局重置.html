      🏗️ 第1层：全局重置

      CSS 的地基 —— 先把所有浏览器的默认样式"铲平"，你的样式才能说一不二

      一、box-sizing: border-box —— CSS第一重要的属性

      1.1 浏览器默认行为：content-box（坑人的默认值）

      浏览器默认的盒模型叫 content-box。它的逻辑是： 你设的 width 只代表"内容区的宽度"， padding（内边距）和 border（边框）是另外加上去的。 

      /* content-box（浏览器默认）下：*/
.box {
    width: 200px;        /* 内容区宽度 = 200px */
    padding: 20px;        /* 左右各加20px */
    border: 5px solid;    /* 左右各加5px */
}
/* 实际占据宽度 = 200 + 20×2 + 5×2 = 250px！ */
/* 你写的200px，实际占了250px——多了25%！ */

      直观演示：两个50%宽度的盒子并排

      （下面的盒子用了 width:50%; padding:20px;，观察它们能不能并排）

      ❌ content-box（浏览器默认）

      width: 50% + padding: 20px

      → 实际宽度超过50%

      → 两个盒子并排会溢出

      → 第二个盒子被挤到下一行

      ✅ border-box（重置后）

      width: 50% 就真的是50%

      → padding 和 border 都算在50%里面

      → 两个盒子正好并排

      → 布局不会崩

      1.2 border-box 的工作原理

      box-sizing: border-box 的意思是："边框也算在宽度里面"。
      你设 width: 200px，元素总宽度就是200px，浏览器自动帮你从内容区里扣掉 padding 和 border 的空间。 

      /* border-box 下：*/
.box {
    box-sizing: border-box;  /* ← 加上这一行 */
    width: 200px;             /* 总宽度 = 200px（不会多） */
    padding: 20px;            /* 内容区自动缩小，给padding腾地方 */
    border: 5px solid;        /* 内容区继续缩小，给border腾地方 */
}
/* 实际占据宽度 = 200px（就是你写的200px！） */
/* 内容区宽度 = 200 - 20×2 - 5×2 = 150px（浏览器自动算了） */
      💡 记忆口诀：
      content-box = 你写的宽度只是内容，padding和border额外加 → 实际宽度 > 你写的 → 坑
      border-box = 你写的宽度就是最终宽度，padding和border算在里面 → 实际宽度 = 你写的 → 省心

      二、你踩过的坑（来自之前的练习）

      ❌ 常见错误1：忘了写 box-sizing: border-box

      症状：明明每个卡片设了 width: calc((100% - 30px) / 3)，结果还是溢出换行了。

      原因：卡片有 padding: 15px，在 content-box 下这 30px 的 padding 是额外加上去的。calc只算了gap，没算padding。

      修复：第一行加上 * { box-sizing: border-box; } 就行了。

      ❌ 常见错误2：ul 宽度写死 900px

      症状：响应式布局里把 ul 设了 width: 900px，手机屏幕375px时内容溢出。

      原因：width: 900px 是固定宽度，不管屏幕多大都是900px。

      修复：用 max-width: 900px; width: 100%; 代替。max-width 限制最大宽度，width:100% 保证小屏幕自动缩小。

      ❌ 常见错误3：图片底部有神秘空隙

      症状：图片放在 div 里，div 底部总是多出 3px 空白，怎么设 margin:0 都消不掉。

      原因：图片默认是 inline 元素，和文字一样按基线对齐，基线下方留了给字母"g、y、j"尾巴的空间——这就是那 3px 的来历。

      修复：img { display: block; } 一行解决。让图片变成块级元素，不再按文字基线对齐。

      三、标准重置模板（建议每个项目开头都复制这段）

      /* ===== 第1层：全局重置 ===== */
/* 作用：清除浏览器默认样式，统一盒模型 */
/* 把这7行放在任何CSS文件的最开头 */

* {
    margin: 0;                 /* 清除默认外边距（body有8px） */
    padding: 0;                /* 清除默认内边距（ul有40px） */
    box-sizing: border-box;    /* 让width就是最终宽度 */
}

ul, ol {
    list-style: none;          /* 去掉列表前面的圆点 */
}

a {
    text-decoration: none;     /* 去掉链接下划线 */
    color: inherit;            /* 链接颜色跟随父元素 */
}

img {
    display: block;            /* 消除图片底部3px幽灵空隙 */
    max-width: 100%;           /* 图片不超过容器宽度 */
    height: auto;              /* 高度自动等比缩放 */
}

      四、因果关系链

      没写 box-sizing: border-box
  → width: 50% 的实际宽度 > 50%
  → 两个"50%"并排，总和超过100%
  → 第二个盒子被挤到下一行
  → 布局崩溃

没写 img { display: block }
  → 图片是 inline 元素
  → 按文字基线对齐，底部留3px给字母尾巴
  → 图片和容器底部之间有3px缝隙
  → 怎么调margin都消不掉

没写 ul { list-style: none }
  → 导航栏每个菜单项前面有个黑圆点
  → 看起来像文档目录，不像导航栏

没写 * { margin: 0; padding: 0 }
  → 不同浏览器给 body、p、h1 的默认margin不同
  → 在Chrome看是居中的，Firefox看就歪了

      五、与其他层的关系

      第1层 → 第2层（间距层）：第2层的 padding/margin/width 能不能算对，完全取决于第1层的 box-sizing 设没设对。

      第1层 → 第3层（排列层）：flex 布局中 flex: 1 要正常分配宽度，前提是第1层的 box-sizing: border-box 已经设好了，否则弹性计算会出错。

      第1层 → 第7层（响应式层）：@media 里的 width: calc() 公式基于 border-box 计算，如果第1层没设好，calc结果会偏小。

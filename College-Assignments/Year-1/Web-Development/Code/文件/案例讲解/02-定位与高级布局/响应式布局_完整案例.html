二、viewport —— 响应式的第一行代码

<!-- 放在 <head> 里，必须写！ -->
<meta name="viewport" content="width=device-width, initial-scale=1.0">
<!--
    width=device-width → 页面宽度=设备屏幕宽度（375px手机就是375，不写的话手机会模拟980px）
    initial-scale=1.0 → 初始缩放比例1:1
    不写这行 → 手机端页面会缩小得像蚂蚁，用户要双指放大才能看
-->

三、min-width vs max-width —— 两种响应式思路

min-width（移动优先）max-width（桌面优先）
默认样式给手机（1列）给大屏（多列）
@media 后缀大屏叠加小屏覆盖
代码量少（手机样式简单）多
推荐✅ 新项目首选老项目兼容

四、calc() 列宽公式 —— 核心公式

/* 通用公式 */
width: calc((100% - (列数-1) × gap值) / 列数)

/* 实际例子（gap=15px） */
1列: width: 100%                          不需要calc
2列: width: calc((100% - 15px) / 2)       减1个gap
3列: width: calc((100% - 30px) / 3)       减2个gap
4列: width: calc((100% - 45px) / 4)       减3个gap
5列: width: calc((100% - 60px) / 5)       减4个gap

/* ★★★ calc() 运算符两边必须有空格！★★★ */
/* ❌ */ width: calc((100%-30px)/3);   /* 无效！CSS引擎直接丢弃整行 */
/* ✅ */ width: calc((100% - 30px) / 3);

❌ 你踩过的坑：calc 空格 + flex-wrap缺失

1. calc((100%-30px)/3) → 没空格 → CSS丢弃 → 宽度回到默认 → 卡片挤在一起

2. 写了@media没写flex-wrap → li还是块级元素一个占一行 → 媒体查询改width也无效

五、完整的响应式卡片模板

/* 第1层 */
*{margin:0;padding:0;box-sizing:border-box;}

/* 第2层 + 第3层：默认移动端样式 */
.card-grid{display:flex;flex-wrap:wrap;gap:15px;}
.card{width:100%;}  /* 移动端1列 */

/* 第7层：按屏幕宽度递增列数 */
@media (min-width:576px){.card{width:calc((100% - 15px) / 2);}}
@media (min-width:768px){.card{width:calc((100% - 30px) / 3);}}
@media (min-width:992px){.card{width:calc((100% - 45px) / 4);}}
@media (min-width:1200px){.card{width:calc((100% - 60px) / 5);}}

六、因果关系链

没写 <meta viewport> → 手机模拟980px → 页面缩成蚂蚁 → 用户双指放大

没写 flex-wrap → 卡片不换行 → 全挤一行溢出 → @media改width也白改

calc没空格 → CSS丢弃整行 → 卡片宽度变默认 → 布局崩

gap和margin同时存在 → 间距变大 → calc只减了gap没减margin → 宽度不对

💡 响应式布局三板斧：

1. display: flex; flex-wrap: wrap; gap: 间距;（第3层）

2. width: calc((100% - 缝隙总和) / 列数);（第2层+第7层）

3. @media (min-width: 断点) { 改列数 }（第7层）

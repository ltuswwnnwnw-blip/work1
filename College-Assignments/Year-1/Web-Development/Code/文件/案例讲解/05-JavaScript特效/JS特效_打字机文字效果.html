一、定时器：JS的"闹钟"

setInterval()setTimeout()
翻译"每隔X毫秒，做一次""X毫秒后，做一次"
执行次数反复执行，直到clearInterval()叫停只执行一次
停止方式clearInterval(定时器ID)自动停
生活类比闹钟每天早上7点都响设一个倒计时，到点响一次
打字机中用途每100ms多显示一个字打完一条后等5秒再打下一条
// setInterval：反复执行
var timer = setInterval(function(){
    显示下一个字();            // 这个函数每100ms被调用一次
}, 100);
// 参数1：要执行的函数
// 参数2：间隔时间（毫秒），100ms = 0.1秒
// 返回值：定时器ID（数字），用于clearInterval来停止它

// clearInterval：停止定时器
clearInterval(timer);
// 不停止会怎样？定时器永远跑下去，占用CPU，用户离开页面也不停
// 而且多个定时器同时跑会互相干扰

// setTimeout：延迟执行一次
setTimeout(function(){
    开始下一条通知();
}, 5000);
// 5000ms = 5秒后执行一次，然后自动结束
// 不需要clearInterval来停止

二、substr()：从字符串里切一段出来

var text = "欢迎来到文馨书屋";

text.substr(0, 1);   // → "欢"   (从位置0开始取1个)
text.substr(0, 2);   // → "欢迎" (从位置0开始取2个)
text.substr(0, 3);   // → "欢迎来"(从位置0开始取3个)

// sub = substring = 子串
// str = string = 字符串
// substr(起始位置, 取几个字)
// 起始位置从0开始数！0=第一个字，1=第二个字

// substring(from, to) 是类似的：substring(0,3) → "欢迎来"（0到3，不包括3）

三、打字机效果原理（核心逻辑）

// 假设通知文字是 "欢迎来到文馨书屋"

// 第100ms：substr(0, 1) → 显示 "欢"
// 第200ms：substr(0, 2) → 显示 "欢迎"
// 第300ms：substr(0, 3) → 显示 "欢迎来"
// ...
// 第900ms：substr(0, 9) → 显示 "欢迎来到文馨书屋"（完整文字）
// → 触发clearInterval()停止 → setTimeout 5秒后开始下一条

// 每次比上一次多显示一个字 → 肉眼看到的就是"一个字一个字往外蹦"

四、完整流程图

页面加载完成(onload)
  → 启动start()函数
  → 取数组里第一条通知文字
  → setInterval每100ms执行一次typeEffect()
      → typeEffect里：substr(0, 当前字数+1)
      → 显示到页面上
      → 当前字数++
      → 如果当前字数 >= 通知总字数：
          → clearInterval() 停止打字
          → setTimeout 5秒后
              → 取数组里下一条通知
              → 重启setInterval打下一段文字

六、因果关系链

setInterval每100ms触发一次
  → typeEffect()被执行 → substr(0, currentChar+1)比上次多取一个字
  → 更新页面 → currentChar++
  → currentChar >= 文字总长度？
      → 是：clearInterval()停打字 → setTimeout 5秒后 → nextNotice()
      → 否：继续等下一个100ms → 重复循环

没有clearInterval会怎样？
  → 第一条通知打完后，定时器还在跑
  → currentChar无限增大 → substr(0, 999)还是那几个字 → 浪费CPU
  → 同时第二条通知的定时器也在跑 → 两个定时器抢着更新同一个位置 → 乱码

❌ 常见错误：忘了clearInterval

症状：第一条通知打完后，永远停不下来，或者新老定时器重叠运行。

原因：setInterval会一直跑，直到clearInterval被调用或页面关闭。

修复：每次启动新定时器前，先clearInterval旧的；每条通知打完后，clearInterval当前定时器。
